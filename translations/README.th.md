ส่วนขยาย Firefox ที่ทำอย่างเดียว คือไม่ให้ Google Analytics วัดผลคุณ
ใช้ได้ทั้งบนเดสก์ท็อปและ Android

*Hakarasenai* แปลว่า "ไม่ปล่อยให้วัด" — และนั่นคือรายการความสามารถทั้งหมด

**มันทำอะไร:**

1. บอกโค้ด Google Analytics บนหน้าเว็บว่าคุณปฏิเสธการติดตามแล้ว
2. บล็อกข้อมูลการวัดผลที่จะถูกส่งออกไปอยู่ดี
3. ให้คุณยกเว้นเว็บไซต์ใดเว็บไซต์หนึ่งได้จากปุ่มบนแถบเครื่องมือ หากมีเว็บไหนงอแง

ไม่มีหน้าตั้งค่า ไม่มีการสมัครรับรายการตัวกรอง ไม่มีตัวนับ ไม่มีรุ่น Pro

## ทำไมถึงมีส่วนขยายนี้

Google มี "Google Analytics Opt-out Add-on" อย่างเป็นทางการ และมีรุ่นสำหรับ
Firefox ด้วย ปัญหาอยู่ที่ **วิธีทำงาน**: มันฉีดอิลิเมนต์ `<script>` เข้าไปในหน้า
และ Firefox ก็เหมือน Safari ตรงที่บังคับใช้ CSP ของหน้านั้นกับ content script ด้วย
บนเว็บไซต์ใดก็ตามที่มี CSP เข้มงวด การฉีดจะถูกบล็อก และการปฏิเสธก็เงียบ ๆ
ไม่ทำอะไรเลย ไม่มีอะไรบอกคุณว่ามันล้มเหลว ซึ่งเป็นวิธีพังที่แย่ที่สุดเท่าที่
เครื่องมือด้านความเป็นส่วนตัวจะพังได้

Hakarasenai ใช้ตะขอเดียวกันนี้ แต่วางไว้ในที่ที่ CSP เอื้อมไม่ถึง แล้วเสริมการ
บล็อกเครือข่ายไว้ข้างหลังเป็นชั้นที่สอง ถ้าชั้นแรกล้มเหลวเมื่อใด ข้อมูลก็ยัง
ไม่ออกไปอยู่ดี

## การติดตั้ง

### จาก AMO

ค้นหาได้ที่ [addons.mozilla.org](https://addons.mozilla.org/) บน Android ก็
ติดตั้งจาก AMO แบบเดียวกัน — ส่วนขยายประกาศ `gecko_android` ไว้ Firefox for
Android จึงเสนอให้ติดตั้ง

### โหลดชั่วคราวจากซอร์ส

ไม่ต้องบิลด์ เปิด `about:debugging#/runtime/this-firefox` เลือก
**Load Temporary Add-on** แล้วเลือกไฟล์ `manifest.json` ของที่เก็บนี้
มันจะอยู่จนกว่าคุณจะปิด Firefox

ต้องใช้ Firefox 128 ขึ้นไป ทั้งบนเดสก์ท็อปและ Android เพราะ content script แบบ
`world: "MAIN"` เพิ่งมาใน 128

หากต้องการสร้างไฟล์ zip สำหรับ AMO:

```bash
make build   # → dist/hakarasenai-<version>.zip
```

`make lint` และ `make run` ใช้ `web-ext` (ครั้งแรก `npx` จะดาวน์โหลดให้)
`make lint` จะแจ้งเตือนสองรายการโดยตั้งใจ: การประกาศการเก็บข้อมูล
(`data_collection_permissions: none`) จะถูกอ่านตั้งแต่ Firefox 140 เป็นต้นไป
เท่านั้น ขณะที่ `strict_min_version` ตั้งไว้ที่ 128 ตัวตรวจจึงชี้ช่องว่างนี้
บนรุ่น 128–139 คีย์นั้นจะถูกข้ามไปเฉย ๆ ซึ่งไม่คุ้มที่จะลดช่วงที่รองรับลงเพียง
เพื่อให้คำเตือนหายไป

### บน Firefox for Android จากซอร์ส

```bash
adb devices                      # หา id ของอุปกรณ์
make run-android DEVICE=<id>
```

ต้องมี adb, เปิด USB debugging บนโทรศัพท์ และเปิด *Remote debugging via USB*
ในการตั้งค่าของ Firefox

## การใช้งาน

มีตัวควบคุมเพียงอย่างเดียว คือปุ่มบนแถบเครื่องมือ มันแสดงสถานะของเว็บไซต์ปัจจุบัน
และมีการกระทำให้เลือกเพียงอย่างเดียว

| สถานะ | ความหมาย |
| --- | --- |
| **กำลังบล็อก** | ทั้งสองชั้นทำงานอยู่บนเว็บไซต์นี้ ค่าเริ่มต้นเป็นแบบนี้ทุกที่ |
| **ยกเว้นอยู่** | ทั้งสองชั้นปิดอยู่บนเว็บไซต์นี้ และไอคอนจะมีป้าย `OFF` |

**ยกเว้นเว็บไซต์นี้** จะใส่เว็บไซต์นั้นทั้งในกฎ `allow` แบบไดนามิก *และ* ใน
`excludeMatches` ของ content script การยกเว้นจึงเกิดขึ้นจริง ไม่ใช่แค่หน้าตา
การยกเว้นมีผล **ที่ระดับโดเมนที่จดทะเบียนได้ และครอบคลุมซับโดเมน**: ยกเว้น
`example.com` จะยกเว้น `www.example.com` และ `shop.example.com` ไปด้วย
และจะมีผลตั้งแต่การโหลดหน้าครั้งถัดไป

สิ่งนี้มีไว้สำหรับตอนที่คุณอยากถูกวัดผลจริง ๆ เช่นตอนตรวจสอบ GA บนเว็บไซต์ของ
ตัวเอง ป้าย `OFF` ไม่ถูกวาดบน Android แต่หน้าต่างป็อปอัปยังบอกอยู่ว่าคุณอยู่ใน
สถานะไหน

## วิธีทำงาน

### ชั้นที่ 1 — ประกาศการปฏิเสธ

`ga.js`, `analytics.js` และ `gtag.js` ล้วนตรวจ
`window._gaUserPrefs.ioo()` (*ioo* = is opted out) ก่อนส่ง และจะหยุดถ้าได้ค่า
true มันคือแฟล็กเดียวกับที่ส่วนเสริมของ Google เองตั้งไว้ — ทางออกฉุกเฉินที่
Google Analytics เตรียมไว้ให้เอง

`src/optout.js` ถูกลงทะเบียนเป็น content script แบบ `world: "MAIN"` ที่
`document_start` แฟล็กจึงอยู่บนอ็อบเจ็กต์ global ของหน้าก่อนที่โค้ดใด ๆ ของ
เว็บไซต์จะทำงาน ไม่มีการแทรกอะไรลงใน DOM จึงไม่มีอะไรให้ CSP บล็อก
เว็บไซต์เองก็เขียนทับแฟล็กไม่ได้: setter เป็นการทำงานเปล่า ๆ แทนที่จะเป็น
พร็อพเพอร์ตี้ที่เขียนไม่ได้ หน้าที่อยู่ใน strict mode ซึ่งกำหนดค่าให้มันจึงถูก
เพิกเฉยแทนที่จะได้ข้อยกเว้น

### ชั้นที่ 2 — บล็อกการส่งข้อมูล

กฎ declarativeNetRequest แบบคงที่ห้าข้อ ใน `rules/ga.json`:

| โดเมน | สิ่งที่ถูกบล็อก |
| --- | --- |
| `*.google-analytics.com` | URL ใดก็ตามที่มี `/collect` — `/collect`, `/j/collect`, `/g/collect`, `/r/collect` และโฮสต์ตามภูมิภาคอย่าง `region1.` |
| `*.google-analytics.com` | `/batch` ช่องทางส่งแบบรวมกลุ่มของ analytics.js |
| `*.analytics.google.com` | `/g/collect` และ `/g/s/collect` ปลายทางตามภูมิภาคของ GA4 |
| `stats.g.doubleclick.net` | `/collect` ใช้เมื่อเปิด Google Signals |

**สิ่งที่ไม่ถูกบล็อก:** `googletagmanager.com` (`gtag.js`, `gtm.js`) และสคริปต์
ที่ `google-analytics.com` เสิร์ฟเอง การปฏิเสธหมายถึงปล่อยให้โค้ดโหลดได้แต่ไม่ให้
มันรายงาน ถ้าฆ่าตัวโหลดเดอร์ทิ้ง ก็จะพาทุกอย่างที่เว็บไซต์ขับเคลื่อนผ่าน Tag
Manager ล้มไปด้วย เพราะมีชั้นที่ 1 GA จึงเงียบแม้จะโหลดมาแล้ว

เนื่องจากไม่มีทรัพยากรของหน้าใดถูกบล็อก ในทางปฏิบัติจึงแทบไม่เคยทำให้เว็บไซต์พัง

## ตรวจสอบว่าใช้ได้จริง

1. เปิดเว็บไซต์ที่ใช้ GA
2. `F12` → **Network** แล้วกรองด้วย `collect`
3. คำขอไปยัง `www.google-analytics.com/g/collect` และพวกเดียวกันควรแสดงเป็นถูก
   บล็อก (`NS_ERROR_ABORTED`) — นั่นคือชั้นที่ 2
4. ในคอนโซล `_gaUserPrefs.ioo()` ควรคืนค่า `true` — นั่นคือชั้นที่ 1
   ถ้าขึ้น `_gaUserPrefs is not defined` แปลว่า content script ไม่ได้ลงทะเบียน
   ดูหัวข้อแก้ปัญหา

## การทดสอบ

```bash
make setup-test   # ครั้งเดียว: ไฟล์ Firefox, geckodriver และ venv ที่มี selenium
make test
```

`setup-test` ติดตั้งลงใน `~/opt/firefox`, `~/.local/bin` และ `.test/` —
ไม่มีแพ็กเกจของระบบ และไม่มีอะไรต้องใช้สิทธิ์ root

**`make unit`** รันตรรกะการยกเว้นกับตัวแทนจำลองของ WebExtension API ใช้แค่ Node
ไม่ต้องมีเบราว์เซอร์

**`make test-browser`** สั่งงาน Firefox แบบ headless จริง ๆ สองรอบ — รอบหนึ่ง
โหลดส่วนขยาย อีกรอบไม่โหลด — แล้วเปรียบเทียบกัน รอบควบคุมนี่แหละคือหัวใจ:
มันพิสูจน์ว่าเครือข่ายเข้าถึงได้จริง และแฟล็กการปฏิเสธมาจากส่วนขยายจริง ๆ
สิ่งที่ตรวจสอบคือ:

- แฟล็กการปฏิเสธถูกตั้ง **รวมถึงบนหน้าที่เสิร์ฟมาพร้อม CSP เข้มงวด** — ซึ่งเป็น
  กรณีที่ส่วนเสริมของ Google เองล้มเหลวอย่างเงียบ ๆ
- เว็บไซต์ที่กำหนดค่าให้ `_gaUserPrefs` ไม่สามารถพาตัวเองกลับเข้าการติดตามได้
  และไม่เกิดข้อยกเว้นขณะพยายาม
- คำขอ `/collect` ของ GA4, Universal Analytics และปลายทางตามภูมิภาคถูกบล็อก
  แม้อยู่ภายใต้ CSP เข้มงวด
- `gtag.js` ยังโหลดได้ และ `/collect` ที่มาจากต้นทางเดียวกันไม่ถูกแตะต้อง
  กล่าวคือกฎไม่ได้บล็อกเกินจำเป็น

บิลด์สำหรับ Android ยังไม่ได้ลองบนอุปกรณ์จริง ทุก API ที่ใช้ถูกตรวจกับ
browser-compat-data ของ MDN แล้วและตรงกับการรองรับบนเดสก์ท็อป แต่นั่นเป็นการ
ตรวจบนกระดาษ ไม่ใช่การทดสอบ

## สิ่งที่มันทำไม่ได้

- **GTM ฝั่งเซิร์ฟเวอร์และการวัดผลแบบ first-party** ถ้าเว็บไซต์เก็บข้อมูลบน
  โดเมนของตัวเอง เช่น `metrics.example.com` แล้วส่งต่อไป GA จากเซิร์ฟเวอร์
  ทราฟฟิกนั้นแยกไม่ออกจากทราฟฟิกปกติที่วิ่งไปยังเว็บไซต์นั้น ชั้นที่ 2 จึงจับ
  ไม่ได้ แต่ชั้นที่ 1 ยังมีผล เพราะผู้ส่งคือ gtag.js บนหน้าเว็บ
- **เครื่องมือวิเคราะห์อื่นที่ไม่ใช่ GA** อยู่นอกขอบเขต ส่วนขยายนี้ปฏิเสธเฉพาะ
  Google Analytics เท่านั้น
- **การส่งจากฝั่งเซิร์ฟเวอร์ล้วนผ่าน Measurement Protocol** ไม่ผ่านเบราว์เซอร์
  เลย จึงไม่มีส่วนขยายเบราว์เซอร์ใดหยุดได้

## ความเป็นส่วนตัว

ส่วนขยายนี้ **ไม่เก็บอะไรเลยและไม่ส่งอะไรไปที่ใด** มันไม่ส่งคำขอเครือข่ายของ
ตัวเอง สิ่งเดียวที่เก็บไว้คือรายชื่อโฮสต์ที่คุณยกเว้น (`storage.local`)
และมันไม่เคยออกจากเครื่อง ไฟล์ manifest ประกาศเรื่องนี้ไว้ว่า
`data_collection_permissions: { required: ["none"] }`

## การเผยแพร่ (บันทึกสำหรับผู้ดูแล)

Firefox จะไม่ติดตั้งส่วนขยายที่ไม่ได้เซ็นอย่างถาวร การแจกจ่ายจึงต้องผ่าน Mozilla
ไม่ทางใดก็ทางหนึ่ง:

- **แบบขึ้นรายการ (listed)** — อัปโหลด `dist/*.zip` ที่
  [AMO Developer Hub](https://addons.mozilla.org/developers/) จะมีการตรวจสอบ
  เซ็นชื่อ แล้วเผยแพร่บน addons.mozilla.org การส่งแบบขึ้นรายการทำอัตโนมัติไม่ได้
  แม้แต่ `web-ext sign --channel=listed` ก็เพียงอัปโหลดเข้าสู่การตรวจสอบเท่านั้น
- **แบบไม่ขึ้นรายการ (unlisted)** คือแจกจ่ายเอง — `make sign` พร้อม
  [คีย์ API ของ AMO](https://addons.mozilla.org/developers/addon/api/key/)
  จะคืนไฟล์ `.xpi` ที่เซ็นแล้วให้คุณโฮสต์เอง แต่โปรดทราบว่าส่วนเสริมที่แจกจ่ายเอง
  ติดตั้งบน Firefox for Android ไม่ได้

ไม่จำเป็นต้องแนบซอร์ส เพราะที่นี่ไม่มีอะไรถูก minify หรือ bundle

## แก้ปัญหา

- **`_gaUserPrefs` เป็น undefined** — น่าจะถูกเพิกถอนสิทธิ์เข้าถึงเว็บไซต์ ให้เปิด
  **สิทธิ์** ของส่วนขยายนี้ใน `about:addons` แล้วอนุญาตให้เข้าถึงทุกเว็บไซต์
  เมื่อสิทธิ์กลับมา มันจะลงทะเบียนตัวเองใหม่ทันที
- **บน Firefox 127 หรือเก่ากว่าไม่มีอะไรเกิดขึ้น** — content script แบบ
  `world: "MAIN"` ต้องใช้ Firefox 128 กรุณาอัปเกรด
- **ยกเว้นแล้วแต่ไม่มีผล** — การยกเว้นมีผลระดับโดเมน ครอบคลุมซับโดเมน และมีผล
  ตั้งแต่การโหลดหน้าครั้งถัดไป
- **เว็บไซต์พังและยกเว้นแล้วก็ไม่หาย** — แสดงว่าไม่ใช่เพราะส่วนขยายนี้ เพราะมัน
  บล็อกเฉพาะคำขอ `/collect` ไม่เคยบล็อกสคริปต์หรือทรัพยากรของหน้าเลย
